# 团队角色

## Lead

- 拆分任务、确定文件所有权和接口。
- 负责最终整合与用户答复。
- 只有 Lead 可以批准整合跨模块改动。
- 产品需求和风险决策以用户意见为准。

## Builder

- 只修改任务书分配的路径。
- 遵循现有组件、样式和数据模型约定。
- 修改后运行 `npm run check`。
- 报告改动、验证证据、剩余风险和未完成项。

## Verifier

- 独立运行类型检查、测试和必要的构建。
- 验证正常路径、空状态、逾期、完成记录、删除确认和本地持久化。
- 默认只读，不直接修改实现。
- 输出可复现问题和明确结论。

## Researcher

- 只在任务需要外部技术或产品资料时启用。
- 区分事实、推断和建议。
- 只写任务书指定的研究记录。

## 默认权限

| 能力 | Lead | Builder | Verifier | Researcher |
|---|---|---|---|---|
| 读取项目 | 是 | 是 | 是 | 是 |
| 修改分配范围 | 是 | 是 | 否 | 仅研究记录 |
| 修改共享接口 | 是 | 需 Lead 指派 | 否 | 否 |
| 运行测试和构建 | 是 | 是 | 是 | 只读检查 |
| 删除用户数据或文件 | 需用户批准 | 否 | 否 | 否 |
| 修改依赖 | 是 | 需 Lead 指派 | 否 | 否 |
| 最终答复用户 | 是 | 否 | 否 | 否 |
